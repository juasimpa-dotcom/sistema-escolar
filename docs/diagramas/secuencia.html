Diagramas UML · 6 procesos clave

Diagramas de secuencia

Interacción entre actor, SPA, API y base de datos. Las flechas continuas son llamadas; las punteadas, respuestas o mensajes asíncronos. Los marcos alt/opt muestran caminos alternativos.

LlamadaRespuestaResultado exitoso

1. Inicio de sesión

Si las credenciales son válidas se emite un token y se redirige según el rol. Si fallan, la SPA muestra el error y no persiste sesión.

seq-login · AuthController::login

2. Solicitar licencia

El servidor valida el orden de fechas y que no exista otra solicitud pendiente que se solape. Solo el camino sin solape crea la licencia.

seq-licencia-solicitar · LicenciaService::solicitar

3. Resolver licencia

Dirección aprueba o rechaza una licencia pendiente. La resolución notifica al padre. El rechazo exige motivo.

seq-licencia-resolver · LicenciaService::aprobar / rechazar

4. Planilla y corrección de notas

La planilla solo incluye inscritos. El guardado es transaccional. La corrección registra historial y bloquea una segunda modificación.

seq-notas · NotaController / NotaService

5. Toma de asistencia

La API carga inscritos y licencias, fuerza el estado cuando corresponde y guarda en una transacción. Una fecha futura se rechaza antes de escribir.

seq-asistencia · AsistenciaService::registrarToma

6. Citación y visto

Dirección emite la citación; la API valida tipo, unidad y vínculo tutor–estudiante, notifica al destinatario y registra el visto.

seq-citacion · CitacionService / CitacionController
